# App Gateway with App Service Certificate Auto-Renew

Demonstrates how to use an **Azure App Service Certificate** on an **Azure Application Gateway**, using a **Storage Account static website** to serve the HTML file required for Certificate Authority (GoDaddy) PKI domain validation.

See https://peterwynroberts.com/azure/2026/11/15/Using-App-Service-Certs-In-App-Gateway-with-HTML-Challenge.html for a more in-depth post about this.

---

## Architecture & Resources

The Bicep template provisions the following Azure resources:

- **Virtual Network & Subnet**: Dedicated VNet (`vnet-<project>`) and `agw-internal` subnet (`10.0.0.0/24`) for Application Gateway.
- **Storage Account (Static Website)**: General Purpose v2 Storage Account (`st<project>`) with static website hosting (`$web` container) to host the PKI validation file.
- **App Service Plan & Backend Web App**: Linux Free-tier (`F1`) App Service Plan hosting a backend containerized web application.
- **Key Vault**: Azure Key Vault (`kv-<project>`) with Azure RBAC enabled to securely store the certificate.
  - **App Service Certificate Service Principal** (`f3c21649-0979-4721-ac85-b0216b2cf413`): Granted **Key Vault Secrets Officer** permissions to create and update certificate secrets.
  - **User-Assigned Managed Identity** (`id-<project>`): Granted **Key Vault Secrets User** permissions and assigned to Application Gateway to read secrets.
- **Public IP & Application Gateway**: Standard v2 Application Gateway (`agw-<project>`) with Public IP:
  - **HTTP (Port 80)**: Path-based routing forwarding `/.well-known/pki-validation/godaddy.html` to the Storage Account static website, and all other traffic to the backend Web App.
  - **HTTPS (Port 443)**: SSL termination routing to the backend Web App once the certificate is bound.
- **App Service Certificate Order**: `Microsoft.CertificateRegistration/certificateOrders` paired with a child certificate binding that links the order to Key Vault.

## How HTML PKI Domain Validation Works

To issue an App Service Certificate without DNS TXT records, GoDaddy (the Certificate Authority powering Azure App Service Certificates) validates domain ownership via an HTTP GET request:

1. **Validation URL**:
   ```
   http://<customDomain>/.well-known/pki-validation/godaddy.html
   ```
2. **Validation Content**:
   The response must be plain text containing solely the `domainVerificationToken` generated by the certificate order (e.g. `f29pje21sk9kqh7o2ah6svqil3`).
3. **Application Gateway Routing**:
   Port 80 traffic for `/.well-known/pki-validation/godaddy.html` is forwarded by Application Gateway directly to the Storage Account's `$web` backend pool, allowing GoDaddy's automated crawlers to validate domain ownership seamlessly.
4. **Certificate Issuance & Secret Storage**:
   Once GoDaddy validates the file, Azure deposits the issued certificate as a PKCS#12 secret into Key Vault (`certagwcert<guid>`).

> **Note on HTML Validation:** Starting November 2021, certificates issued or renewed via HTML/HTTP validation are issued for the single specified domain only (they do not automatically include the `www` subdomain as a Subject Alternative Name).

## Deployment Steps


### Initial Infrastructure Deployment (`deploy.ps1`)
Deploys the base infrastructure, Key Vault, Storage Account, Web App, Certificate Order, and Application Gateway with an HTTP port 80 listener:

```powershell
./deploy.ps1 -ResourceGroupName "rg-agwcert"
```



### Manual Step: DNS Configuration
Ensure your custom domain or subdomain (e.g. `cert-test.peterwynroberts.com`) has a DNS `CNAME` or `A` record pointing to the Application Gateway Public IP address so that GoDaddy's HTTP crawler reaches the gateway.

### Second Deployment to Bind Certificate (`deploy.ps1`)
Once GoDaddy validates the domain and issues the certificate into Key Vault, re-run `deploy.ps1` with the Key Vault secret name obtained in Step 2:

```powershell
./deploy.ps1 -ResourceGroupName "rg-agwcert" -SslCertificateSecretName "<keyVaultSecretName>"
```

This attaches the SSL certificate from Key Vault to Application Gateway, enabling the HTTPS port 443 listener and routing rules.

### Ongoing: Sync Validation Token (`sync-validation-token.ps1`)
Fetches the `domainVerificationToken` and Key Vault `keyVaultSecretName`, generates `godaddy.html`, uploads it to the Storage Account `$web` container, and requests domain verification from Azure.

This script executes quickly without any blocking polling loops. It is designed to run both at initial deployment time and on a recurring schedule in a CI/CD pipeline:

```powershell
./sync-validation-token.ps1 -ResourceGroupName "rg-agwcert"
```

The token sync is done automatically as part of the static site deployment on 1st run.

## Useful CLI Commands

### Fetch Domain Verification Token
```bash
az resource show \
  --resource-group rg-agwcert \
  --resource-type "Microsoft.CertificateRegistration/certificateOrders" \
  --name certagwcert \
  --query "properties.domainVerificationToken" \
  --output tsv
```

### Fetch Key Vault Secret Name
```bash
az resource show \
  --resource-group rg-agwcert \
  --resource-type "Microsoft.CertificateRegistration/certificateOrders" \
  --name certagwcert \
  --query "properties.certificates.certagwcert.keyVaultSecretName" \
  --output tsv
```
